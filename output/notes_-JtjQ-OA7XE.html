Fundamentals of Video Streaming Architecture: From Frame Sequences to Adaptive Bitrate Delivery (HLS & MPEG‑DASH)

** A video is, at its core, a temporally ordered series of still images (frames) that the human visual system integrates into the perception of motion. Mathematically, a video can be modeled as a discrete‑time signal **V[t]**, where each time index *t* corresponds to a frame *Fₜ* ∈ ℝH×W×C (height × width × color‑channels). The frame‑rate *r* (frames per second, fps) defines the sampling interval Δt = 1/*r*. The raw data rate *R* (bits / second) is therefore \[ R = r \times H \times W \times C \times b, \] where *b* is the bits per pixel after colour‑space conversion (e.g., 8 bits per channel for Y′CBCR). Because *R* for uncompressed video quickly exceeds the capacity of typical broadband links, a compression function **C(·)** is applied, yielding a compact representation *S = C(V)*. Modern codecs (H.264/AVC, H.265/HEVC, AV1) formulate compression as an optimization problem that minimizes a Lagrangian cost \[ J = D(V, \hat V) + \lambda \, B, \] where *D* is a distortion metric (e.g., sum of squared differences, SSIM), *B* is the resulting bitrate, and λ balances quality against bandwidth. The encoder searches for motion vectors, intra‑prediction modes, and transform coefficients that satisfy the rate‑distortion trade‑off under constraints such as maximum latency and decoder complexity. In an adaptive‑bitrate (ABR) delivery pipeline, the encoded bitstream is first **segmented** into fixed‑duration chunks (typically 2–10 s). Each chunk is stored in multiple **representations** (renditions) that differ in resolution, frame‑rate, and target bitrate. A manifest file (M3U8 for HLS, MPD for MPEG‑DASH) enumerates these renditions and provides URLs for each segment. At playback time, the client runs a **rate‑adaptation algorithm** (e.g., buffer‑based, throughput‑based, or hybrid) that continuously estimates available bandwidth *B̂* and selects the highest‑quality rendition whose average bitrate *bᵢ* satisfies *bᵢ ≤ α·B̂* (α ≈ 0.8 to leave headroom). The client then issues HTTP GET requests for the chosen segment URLs, leveraging standard CDN caching and HTTP range requests to minimize latency. A concrete Python illustration of the transformation pipeline is shown below. The code uses `ffmpeg-python` to transcode a source file into three ABR renditions, slices them into 4‑second segments, and generates an HLS manifest. To mitigate piracy, providers integrate DRM (Widevine, PlayReady, FairPlay) that encrypts each segment with a per‑session key delivered via the license server. The encryption must be performed **before** segment generation or on‑the‑fly using AES‑CTR, ensuring that the clear‑text key never traverses the CDN. 2. **Edge‑Case Handling** – Network variability can cause buffer underruns, leading to stalls. Implementing **fallback renditions** (e.g., a low‑bitrate “audio‑only” stream) and **segment‑level redundancy** (duplicate keyframes, forward error correction) reduces stall probability. Additionally, the manifest must include `#EXT-X-ALLOW-CACHE:NO` for live streams to prevent stale segment caching. 3. **Scalability & CDN Integration** – Segment files are immutable, enabling aggressive caching at edge nodes. However, the manifest must be **cache‑busted** on each update (e.g., by appending a version query string) to avoid clients receiving stale rendition lists. Horizontal scaling of the encoding pipeline is achieved via containerized workers (Docker/Kubernetes) that pull jobs from a message queue (Kafka, SQS) and write output to an object store (S3, GCS) with lifecycle policies that transition older segments to cold storage. 4. **Observability & QoE Metrics** – Real‑time telemetry (startup latency, rebuffer ratio, average bitrate, bitrate switches) is collected via client‑side SDKs and fed into a time‑series database. These metrics drive automated **autoscaling policies** for both encoding farms and edge cache nodes, ensuring that spikes in demand (e.g., live events) do not degrade user experience. By rigorously applying the rate‑distortion theory, automating the segment‑generation workflow, and embedding security, scalability, and observability primitives, a modern video streaming platform can deliver seamless, adaptive playback across heterogeneous networks and devices. --- **

"""
Video Streaming Architecture Demo
================================

This script demonstrates the core concepts of video streaming
from raw frame sequences to adaptive bitrate delivery using

Key stages illustrated:

1.  Represent a video as a sequence of frames.
2.  Encode the video into multiple bitrate streams.
3.  Generate HLS master and media playlists.
4.  Simulate a client that adapts its bitrate based on
    fluctuating network bandwidth.

The output is a set of dummy segment files and playlist

import os
import pathlib
import random
import time

# Step 1: Define basic data structures
# ----------------------------------------------------------------------
class Frame:
    """
    A single video frame.
    For simulation purposes, a frame is just an integer index.
    """
    def __init__(self, index: int):
        self.index = index

class Video:
    """
    A video represented as a list of frames.
    """
    def __init__(self, duration_sec: float, fps: float):
        self.duration_sec = duration_sec
        self.fps = fps
        self.frames: List[Frame] = [
            Frame(i) for i in range(int(duration_sec * fps))
        ]

# ----------------------------------------------------------------------
def encode_to_segments(
    video: Video,
    segment_duration: float,
    bitrates_kbps: List[int],
    output_dir: pathlib.Path
) -> Dict[int, List[pathlib.Path]]:
    """
    Encode the video into multiple bitrate streams.
    Each bitrate stream is split into fixed‑length segments.

    Parameters
    ----------
    video : Video
        The source video.
    segment_duration : float
        Duration of each segment in seconds.
    bitrates_kbps : List[int]
        List of target bitrates (e.g., [300, 800, 1200]).
    output_dir : pathlib.Path
        Directory where segment files will be written.

    Returns
    -------
    Dict[int, List[pathlib.Path]]
        Mapping from bitrate to list of segment file paths.
    """
    output_dir.mkdir(parents=True, exist_ok=True)
    segments_per_bitrate: Dict[int, List[pathlib.Path]] = {}

    for bitrate in bitrates_kbps:
        bitrate_dir = output_dir / f"{bitrate}k"
        bitrate_dir.mkdir(exist_ok=True)
        segments: List[pathlib.Path] = []

        # Number of segments = ceil(total duration / segment duration)
        num_segments = int(
            (video.duration_sec + segment_duration - 1e-6) // segment_duration
        )

        for seg_idx in range(num_segments):
            # In a real encoder, the segment would contain compressed frames.
            # Here we just create an empty file to represent it.
            seg_file = bitrate_dir / f"segment{seg_idx:04d}.ts"
            seg_file.touch()
            segments.append(seg_file)

        segments_per_bitrate[bitrate] = segments

    return segments_per_bitrate

# ----------------------------------------------------------------------
def generate_hls_playlists(
    segments_per_bitrate: Dict[int, List[pathlib.Path]],
    segment_duration: float,
    output_dir: pathlib.Path
) -> pathlib.Path:
    """
    Create a master playlist and one media playlist per bitrate.

    Parameters
    ----------
    segments_per_bitrate : Dict[int, List[pathlib.Path]]
        Mapping from bitrate to segment files.
    segment_duration : float
        Duration of each segment in seconds.
    output_dir : pathlib.Path
        Directory where playlists will be written.

    Returns
    -------
    pathlib.Path
        Path to the master playlist file.
    """
    master_playlist = output_dir / "master.m3u8"
    with master_playlist.open("w") as mp:
        mp.write("#EXTM3U\n")
        mp.write("#EXT-X-VERSION:3\n")

        for bitrate, segments in sorted(segments_per_bitrate.items()):
            # Compute average bandwidth in bits per second
            bandwidth_bps = bitrate * 1000
            # URI of the media playlist
            media_playlist_name = f"{bitrate}k.m3u8"
            mp.write(
                f"#EXT-X-STREAM-INF:BANDWIDTH={bandwidth_bps},RESOLUTION=640x360\n"
                f"{media_playlist_name}\n"
            )

            # Write media playlist
            media_playlist_path = output_dir / media_playlist_name
            with media_playlist_path.open("w") as mp2:
                mp2.write("#EXTM3U\n")
                mp2.write("#EXT-X-VERSION:3\n")
                mp2.write(f"#EXT-X-TARGETDURATION:{int(segment_duration)+1}\n")
                mp2.write("#EXT-X-MEDIA-SEQUENCE:0\n")

                for seg_file in segments:
                    mp2.write(f"#EXTINF:{segment_duration:.3f},\n")
                    # URI relative to the playlist location
                    mp2.write(f"{seg_file.name}\n")

                mp2.write("#EXT-X-ENDLIST\n")

    return master_playlist

        """
        Simple ABR logic: pick the highest bitrate that is <= measured bandwidth.
        """
        for br in reversed(self.available_bitrates):
            if br * 1000 <= measured_bps:

        Simulate playback by 'downloading' each segment.

            time.sleep(0.05)

            # Measure bandwidth and adapt
            bw = self.measure_bandwidth()
            self.select_bitrate(bw)

            print(
                f"Playing {seg.name} at {self.current_bitrate}k "
                f"(measured {int(bw)} kbps)"
            )

Key Takeaways

  • Video is fundamentally a rapid sequence of still images (frames); mastering frame rate, keyframes, and GOP structure is essential for efficient encoding and smooth playback.
  • Delivering media in small, HTTP‑served segments via a CDN enables scalable distribution; progressive download is simple but cannot adapt to changing network conditions.
  • Adaptive bitrate (ABR) automatically switches between multiple quality levels in real time, ensuring a consistent viewing experience even on unstable connections.
  • HLS and MPEG‑DASH both use manifest files (M3U8 for HLS, MPD for DASH) to describe available segments and bitrate variants, making them the de‑facto standards for ABR streaming.
  • A practical streaming stack combines an encoder pipeline, a packaging tool that generates segment/manifest pairs, CDN distribution, and a player that interprets the manifest and performs bitrate switching.

#!/usr/bin/env python3
"""
Demo script for the concepts discussed in the lecture
“From Full‑File Download to Real‑Time Streaming”.

It shows:
1️⃣  Progressive (buffered) download of a large video file using only the
    Python standard library.
2️⃣  How a “playback” can be started once a configurable buffer size is
    reached – the core idea behind streaming.
3️⃣  A minimal wrapper around **ffmpeg** to push a local file to an RTMP
    endpoint (real‑time messaging protocol).  ffmpeg is an external binary
    but the wrapper itself uses only the standard library (subprocess).

The script is self‑contained and can be run on any modern Python 3.x
installation (≥3.8).  For the RTMP part you need a reachable RTMP server
(e.g. nginx‑rtmp, Wowza, Red5) and ffmpeg installed and available on the
system PATH.
"""

# --------------------------------------------------------------------------- #
# Step 0: Imports & global configuration
# --------------------------------------------------------------------------- #
import argparse
import os
import sys
import time
import urllib.request
from pathlib import Path
from subprocess import PIPE, Popen

# --------------------------------------------------------------------------- #
# Step 1: Helper – human‑readable byte formatting
# --------------------------------------------------------------------------- #
def _fmt_bytes(num: int) -> str:
    """Return a human readable string for *num* bytes."""
    for unit in ("B", "KB", "MB", "GB", "TB"):
        if num < 1024:
            return f"{num:.2f} {unit}"
        num /= 1024
    return f"{num:.2f} PB"


# --------------------------------------------------------------------------- #
# Step 2: Progressive (buffered) download implementation
# --------------------------------------------------------------------------- #
def progressive_download(
    url: str,
    dest: Path,
    chunk_size: int = 256 * 1024,          # 256 KB – a good trade‑off for I/O
    buffer_threshold: int = 5 * 1024 * 1024,  # start playback after 5 MB
) -> None:
    """
    Download *url* to *dest* in small chunks while simulating a playback
    start once *buffer_threshold* bytes have been written.

    Parameters
    ----------
    url
        HTTP/HTTPS URL of the video (or any large binary) to download.
    dest
        Path where the file will be stored.
    chunk_size
        Number of bytes read from the network per iteration.
    buffer_threshold
        Minimum buffered data (in bytes) required before “playback” begins.
    """
    dest.parent.mkdir(parents=True, exist_ok=True)

    # Open the remote resource – urllib automatically follows redirects.
    with urllib.request.urlopen(url) as response, dest.open("wb") as out_file:
        total_size = int(response.info().get("Content-Length", 0))
        print(f"📦 Starting download: {_fmt_bytes(total_size)}")
        downloaded = 0
        buffered = 0
        playback_started = False
        start_time = time.time()

        while True:
            chunk = response.read(chunk_size)
            if not chunk:                     # EOF
                break

            out_file.write(chunk)
            downloaded += len(chunk)
            buffered   += len(chunk)

            # Simple progress indicator (updates in‑place)
            elapsed = time.time() - start_time
            speed   = downloaded / elapsed if elapsed > 0 else 0
            percent = (downloaded / total_size) * 100 if total_size else 0
            sys.stdout.write(
                f"\r🔽 {percent:5.1f}% "
                f"({_fmt_bytes(downloaded)}/{_fmt_bytes(total_size)}) "
                f"@ {_fmt_bytes(speed)}/s"
            )
            sys.stdout.flush()

            # ----------------------------------------------------------- #
            # Step 2‑a: Simulated playback trigger
            # ----------------------------------------------------------- #
            if not playback_started and buffered >= buffer_threshold:
                playback_started = True
                print("\n▶️  Buffer threshold reached – starting playback simulation")
                # In a real player you would hand over the buffered bytes to a decoder.
                # Here we just sleep a bit to illustrate that playback can run
                # concurrently with the remaining download.
                # (In production you would use threading / asyncio.)
                # For demo purposes we just print a message.
                print("   ... (playback would be happening now) ...")

        # End of download loop
        print("\n✅ Download completed")
        total_time = time.time() - start_time
        print(f"⏱️  Total time: {total_time:.2f}s ({_fmt_bytes(total_size/total_time)}/s)")

# --------------------------------------------------------------------------- #
# Step 3: Minimal RTMP push wrapper (requires ffmpeg)
# --------------------------------------------------------------------------- #
def push_to_rtmp(
    input_file: Path,
    rtmp_url: str,
    ffmpeg_path: str = "ffmpeg",
    overwrite: bool = True,
) -> None:
    """
    Push *input_file* to an RTMP endpoint using ffmpeg.

    This demonstrates how a local video can be turned into a real‑time
    stream (the “RTMP” protocol mentioned in the lecture).

    Parameters
    ----------
    input_file
        Path to the source video file.
    rtmp_url
        Destination RTMP URL, e.g. ``rtmp://myserver/live/stream``.
    ffmpeg_path
        Name or full path of the ffmpeg binary.
    overwrite
        If True, add ``-y`` to ffmpeg args to overwrite existing output.
    """
    if not input_file.is_file():
        raise FileNotFoundError(f"Input file not found: {input_file}")

    cmd = [
        ffmpeg_path,
        "-re",                     # read input at native frame rate (simulate live)
        "-i", str(input_file),
        "-c:v", "copy",            # no re‑encoding – keep original codec
        "-c:a", "aac", "-b:a", "128k",
        "-f", "flv",               # RTMP uses FLV container
    ]
    if overwrite:
        cmd.append("-y")
    cmd.append(rtmp_url)

    print("\n🚀 Starting RTMP push (ffmpeg command):")
    print(" ".join(cmd))

    # Run ffmpeg as a subprocess; capture stdout/stderr for debugging.
    process = Popen(cmd, stdout=PIPE, stderr=PIPE, text=True)

    try:
        # Forward ffmpeg logs to the console in real time.
        while True:
            line = process.stderr.readline()
            if not line:
                break
            sys.stdout.write(line)
    finally:
        process.wait()
        if process.returncode == 0:
            print("\n✅ RTMP push finished successfully")
        else:
            print(f"\n❌ ffmpeg exited with code {process.returncode}")

def main() -> None:
    args = _parse_args()

    if args.command == "download":

Key Takeaways

  • Full‑file downloads of 4–5 GB 4K/8K videos can still take 6–7 minutes even on 200 Mbps links, wasting bandwidth and causing poor playback on low‑end devices.
  • Chunked streaming lets the player start playback before the entire file is received, dramatically cutting wait times and reducing wasted data.
  • RTMP (Adobe) and RTSP (RealNetworks) are the two core protocols that enable real‑time chunked delivery, handling packet ordering, timing, and retransmission.
