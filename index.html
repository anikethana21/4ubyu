4 U BY UFOR YOU BY YOU

A lecture becomes notes you can keep.

Open the YouTube lecture you are already watching, press one button, and get a chapterised study handbook — chapters by topic, timestamps that jump to the right minute, one self-contained HTML page you can keep, print, or save as a PDF. No account, no server, no upload. The notes are written by your own API key, and the page opens from your own disk for as long as you have it.

＋ Install 4 U By U

A userscript: install Tampermonkey or Violentmonkey first, then click the button — the manager opens its own install confirmation. It updates itself from this page as the script changes, so there is nothing to reinstall.

Three minutes to your first lecture

1Open a lecture on YouTube. A ✦ Make notes button appears in the corner.
2Paste an API key. Get a free one from console.groq.com/keys — it stays in your browser, and the model list is asked of the provider with your key, so you always see the models you actually have.
3The cost is shown before it is spent: how many calls, roughly how many tokens, and how many lectures of this size the model's free day holds.
4Press Generate. When it finishes, open the page or download it. One click in the page turns it into a PDF, using your browser's own printer.

What it will not do

It will not invent a chapter it could not read. If a part of the lecture cannot be written up, that part says so on the page, in words, with the provider's own reason and with the lecture's own words for that stretch underneath — a heading that looks real but was made up would be worse than a gap.

Free tiers meter tokens per minute, so a long lecture waits between calls instead of failing; a finished part is kept, so a closed tab, a rate limit or a dead battery costs you the wait and not the work.

How long a lecture can be

There is no length limit in the app. The limit is the model's daily allowance. On Groq's free tier, with captions at a normal speaking pace:

  • 15–30 minutes — several lectures a day.
  • 1 hour — about 42k tokens; four a day.
  • 2 hours — about 85k tokens; two a day.
  • 4 hours — about 170k tokens; one a day, with little to spare.
  • 6 hours and beyond — needs a 500k/day model (llama-3.1-8b-instant, qwen/qwen3-32b).

Before it spends anything, the panel subtracts what your day has already used. If the lecture will not fit, Generate is disabled and it names the models that still have room. The provider's own limit stays the final word; a run that stops there keeps every part already written and continues tomorrow.

English captions only

The notes are written in English, from English captions — the prompts, the section structure and every notice are English, and a lecture in another script produced notes worse than none. So the captions are checked before the first API call. Hindi, Arabic, Chinese, Japanese, Korean, Russian and other non-Latin scripts are refused with the real percentage of Latin letters, and nothing is spent.

The limit is script, not language: French, Spanish, German and other Latin-script lectures are not detected, and will be written up in English from captions that are not English. For those, turn on YouTube's English translation of the captions first and the notes will be written from that track.

Your key, your machine

Nothing is uploaded. The captions are read in your browser from the page you are already on. The only request that leaves your machine goes to the provider you picked, with your key, for the notes you asked for.

Your key stays yours. It is stored by your script manager, in your browser. There is no server of ours to send it to — there is no server at all.

It is not "unhackable" and no software is. What is true: no account, no analytics, no third-party script, no CDN, and no address in the notes page that could call home later. Read the source — the whole program is one file, and the parts that decide what the notes say are tested without a browser.

Also available as an extension

The same program is built as a Chrome extension (extension/dist/store/, and npm run package to zip it for the store). It is the userscript with three script-manager functions swapped for browser ones; the notes are written by the code the tests ran.
